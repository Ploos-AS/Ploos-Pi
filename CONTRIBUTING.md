# Contributing

Thank you for helping develop reliable open hardware.

## Workflow
Open an issue stating problem, evidence and affected SKU. For material architecture decisions submit an ADR. Use PRs for documentation/design changes and link requirement IDs and test evidence. Clearly mark assumptions, targets and verified results.

## Design contributions
Keep KiCad projects reproducible. Document footprint sources, manufacturing constraints, stack-up, impedance, connector specifications, testpoints and parts availability. Do not upload proprietary/NDA datasheets or licensed commercial board files.

## Review
Electrical/thermal/high-speed/firmware/security changes require domain review. Production-bound changes require explicit verification and BOM revision updates. Do not merge hypothetical benchmarks or unsupported compliance/availability claims.

## Reporting
Include actual reproduction steps for errors; redact passwords, private keys, serial identifiers and personal data.
